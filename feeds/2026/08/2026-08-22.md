## Late-Breaking AI Signal

### Claude Code's effort setting exposed a serving-contract gap

- **What changed:** A [Claude Code investigation](https://x.com/argofowl/status/2091145834968850821) reached `473,829` views from `5,302` current followers (`89.37x`), followed by [HN at `159 / 150`](https://news.ycombinator.com/item?id=49401549) and indexed Reddit discussions at `144` and `46` votes. Anthropic's Claude Code lead [confirmed an API-serving-config A/B test that maps numerical effort values differently](https://x.com/trq212/status/2091247114869432543), while saying the displayed number is not a `0-100` capability scale and internal evals found no regression.
- **Why builders should care:** A user-facing effort label is part of the operating contract even when the hidden number changes. Preserve requested effort, observable traces, tokens, tool calls, latency, tests, and accepted output so a serving change can be evaluated on completed work.
- **Boundary:** This confirms a configuration experiment, not a proven model-quality reduction. The timely proof is one fixed-task, multi-run receipt—not a “Claude got nerfed” recap.
- **Heat:** `single segment`; `attention_heat 87.1`, `builder_fit 94.9`, captured `17:07 PDT`.

## Builder Takeaways

- Build: add one measurable receipt to an existing agent workflow—cost per accepted result, interventions, elapsed time, permissions, and final evidence.
- Study: separate intent, containment, and execution by comparing Huzzah, `gh-aw`, and Codex.
- Ignore: broad “agent across every app” positioning until it names a workflow, trust boundary, and observable outcome.
