## GitHub / Repo Radar

- Repo: [cathrynlavery/diagram-design](https://github.com/cathrynlavery/diagram-design)
  - What it does: provides 29 editorial diagram types as self-contained HTML
    and SVG artifacts for Claude Code.
  - Why builders should care: focused output contracts can create more trust
    than another general-purpose generation interface.
  - Source: [GitHub](https://github.com/cathrynlavery/diagram-design)
- Repo: [google/skills](https://github.com/google/skills)
  - What it does: publishes official agent skills for Google products and
    technologies.
  - Why builders should care: it is a useful reference for vendor-owned skill
    packaging, but also a prompt to inspect trust and portability boundaries.
  - Source: [GitHub](https://github.com/google/skills)
- Repo: [cactus-compute/needle](https://github.com/cactus-compute/needle)
  - What it does: presents a `14MB` foundation-model approach for phones,
    wearables, smart-home devices, and robots.
  - Why builders should care: edge-model claims become useful only when the
    task, hardware, latency, and quality boundary are explicit.
  - Source: [GitHub](https://github.com/cactus-compute/needle)
- Repo: [NanoNets/Graft](https://github.com/NanoNets/Graft)
  - What it does: adds code-aware hooks for coding agents and claims a `42%`
    reduction in grep-token use.
  - Why builders should care: token savings are interesting only if context
    freshness and correctness survive the optimization.
  - Source: [GitHub](https://github.com/NanoNets/Graft)
- Repo: [metedata/Remarc](https://github.com/metedata/Remarc)
  - What it does: turns comments on text, screenshots, UI elements, and voice
    into structured feedback that coding agents consume over MCP.
  - Why builders should care: it targets the last-mile polish gap between a
    generated prototype and a deliberately finished product.
  - Source: [GitHub](https://github.com/metedata/Remarc)

## Builder Takeaways

- Build: one accepted-task model receipt with hardware or cost, latency,
  interventions, verification, and final artifact.
- Study: Google Skills for catalog boundaries, Diagram Design for inspectable
  artifact packaging, and Remarc for structured human feedback.
- Ignore: unsupported adoption claims, stale leaderboards, and the urge to
  clone every new agent stack before proving one useful boundary.
