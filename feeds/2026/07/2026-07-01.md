# George's Builder Radar - 2026-07-01

Updated when George ran his morning routine.

## Top Signals

- Signal: Agent products are converging on orchestration, not just one-off code generation.
  - Why it matters: X, GitHub, Product Hunt, and Launch HN all repeated the same need: manage many agents, preserve context, run browser/worktree tasks safely, and keep humans in review.
  - Source: https://x.com/PaulSolt/status/2072333522765754581, https://news.ycombinator.com/item?id=48236770, https://www.producthunt.com/

- Signal: Browser automation is becoming an agent runtime category.
  - Why it matters: Tabstack, Intuned, BrowserAct, and related repos are positioning browser control as infrastructure for agents rather than a fragile scraping hack.
  - Source: https://www.producthunt.com/, https://news.ycombinator.com/launches

- Signal: Agent memory and design contracts are turning into durable product surfaces.
  - Why it matters: codebase-memory MCP, `design.md`, Astryx, Hyper, and Humalike all point at the same market gap: agents need structured context and social/design rules they can reuse.
  - Source: https://github.com/DeusData/codebase-memory-mcp, https://github.com/google-labs-code/design.md, https://github.com/facebook/astryx

## GitHub / Repo Radar

- Repo: https://github.com/msitarzewski/agency-agents
  - What it does: Packages a large set of specialized "AI agency" agents.
  - Why builders should care: The category is moving toward agent role libraries and operational departments, though the very large star count deserves quality inspection before adoption.
  - Source: https://github.com/msitarzewski/agency-agents

- Repo: https://github.com/usestrix/strix
  - What it does: Open-source AI penetration testing for finding and fixing application vulnerabilities.
  - Why builders should care: Security scanning is being reworked as agentic attack-path and repair loops.
  - Source: https://github.com/usestrix/strix

- Repo: https://github.com/facebook/astryx
  - What it does: Agent-ready customizable design system.
  - Why builders should care: Design systems increasingly need machine-readable contracts so coding agents can preserve UI intent.
  - Source: https://github.com/facebook/astryx

- Repo: https://github.com/google-labs-code/design.md
  - What it does: Format specification for describing visual identity to coding agents.
  - Why builders should care: `DESIGN.md` looks like an emerging pattern for persistent design context in agent-built apps.
  - Source: https://github.com/google-labs-code/design.md

- Repo: https://github.com/DeusData/codebase-memory-mcp
  - What it does: High-performance MCP server that indexes codebases into a persistent knowledge graph.
  - Why builders should care: Repo memory is becoming infrastructure for coding agents, handoffs, and low-token context retrieval.
  - Source: https://github.com/DeusData/codebase-memory-mcp

- Repo: https://github.com/calesthio/OpenMontage
  - What it does: Agentic video production system with pipelines, tools, and skills.
  - Why builders should care: Video production is a strong proof-object category for agent workflows because output quality is visible and testable.
  - Source: https://github.com/calesthio/OpenMontage

- Repo: https://github.com/xbtlin/ai-berkshire
  - What it does: Claude Code / Codex value-investing research framework with multi-agent adversarial analysis.
  - Why builders should care: Good example of encoding expert methodology as repeatable agent workflows, independent of whether the investing domain is relevant.
  - Source: https://github.com/xbtlin/ai-berkshire

## Builder Takeaways

- Build: A tiny "chief-of-staff agent loop" proof object: issue -> worker agent -> heartbeat -> tested output -> review notes.
- Study: Superset HN comments, `design.md`, codebase-memory MCP, and Tabstack/Intuned-style browser automation.
- Ignore: Generic AI wrapper launches without a distinct workflow, permission model, or proof artifact.
