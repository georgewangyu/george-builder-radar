# George's Builder Radar - 2026-06-28

Updated when George ran his morning routine.

## Top Signals

- Signal: Agent memory is becoming a product category.
  - Why it matters: X, GitHub, and Product Hunt all pointed at memory as a bottleneck: compact memory, local memory, versioned memory, and codebase memory.
  - Source: https://x.com/mvanhorn/status/2071254741976526884, https://github.com/DeusData/codebase-memory-mcp, https://www.producthunt.com/

- Signal: Multi-agent work creates an inbox and coordination problem.
  - Why it matters: Long-running agents, side agents, and agent inbox products all assume builders will soon manage outputs from many agents at once.
  - Source: https://x.com/petergyang/status/2070879457754439870, https://x.com/steipete/status/2071011669216526788, https://www.producthunt.com/

- Signal: Browser/MCP adapters are becoming the universal connective tissue.
  - Why it matters: WebMCP, Google Analytics MCP, and codebase-memory MCP show the same wedge: let any agent operate inside existing systems instead of inventing a new app.
  - Source: https://www.producthunt.com/, https://github.com/DeusData/codebase-memory-mcp

## X Builder Notes

- Account / post: Gergely Orosz on Anthropic-style internal company agents.
  - Public-safe read: The breakthrough is not "AI in Slack"; it is cloud AI connected to internal company systems with enough reliability and access control to do real work.
  - Source: https://x.com/GergelyOrosz/status/2071126385121452190

- Account / post: Matt Van Horn on cutting agent memory from 218 files to 6.
  - Public-safe read: Always-loaded agent memory can rot into expensive context clutter. Repeated workflows should become skills, while recall should be queryable instead of injected into every session.
  - Source: https://x.com/mvanhorn/status/2071254741976526884

- Account / post: Matt Pocock on a possible `/research` skill.
  - Public-safe read: If you keep giving the same operational instruction to an agent, it probably deserves to become a reusable skill.
  - Source: https://x.com/mattpocockuk/status/2071153298950799868

- Account / post: Tong Chen's NotFair ad audit offer.
  - Public-safe read: A tiny account can still get large distribution when the offer is concrete, cheap, and legible in one line.
  - Source: https://x.com/therealtongchen/status/2069657382440099908

- Account / post: Peter Yang on long-running Claude agents.

## GitHub / Repo Radar

- Repo: `calesthio/OpenMontage`
  - What it does: Open-source, agentic video production system with pipelines, tools, and agent skills.
  - Why builders should care: Video production is a high-friction workflow where agent orchestration can show visible value quickly.
  - Source: https://github.com/calesthio/OpenMontage

- Repo: `DeusData/codebase-memory-mcp`
  - What it does: MCP server that indexes codebases into a persistent knowledge graph for fast code intelligence.
  - Why builders should care: Code memory is becoming the practical version of "agent memory" for software teams.
  - Source: https://github.com/DeusData/codebase-memory-mcp

- Repo: `google-labs-code/design.md`
  - What it does: Format specification for describing visual identity to coding agents.
  - Why builders should care: Design systems need to become agent-readable if agents are going to build product surfaces consistently.
  - Source: https://github.com/google-labs-code/design.md

- Repo: `xbtlin/ai-berkshire`
  - What it does: Claude Code / Codex value-investing research framework with multi-agent adversarial analysis.
  - Why builders should care: Strong example of a vertical research-agent workflow packaged as a repo.
  - Source: https://github.com/xbtlin/ai-berkshire

- Repo: `kunchenguid/no-mistakes`
  - What it does: Lightweight pre-push guardrail.
  - Why builders should care: Agentic coding needs simple verification gates as much as it needs bigger models.
  - Source: https://github.com/kunchenguid/no-mistakes

## Builder Takeaways

- Build: a small proof object that turns one repeated workflow into a reusable skill or public feed.
- Study: agent memory products and repos before adding more always-loaded memory to your own agents.
- Ignore: generic "AI-native GTM" claims unless the launch shows a concrete workflow, data source, and verifier.
