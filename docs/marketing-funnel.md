# Builder Radar Marketing Funnel

## Current Funnel

Builder Radar should not sell itself as an email newsletter first. The first
lead magnet is the installable agent skill.

Flow:

1. Visitor lands on the public radar.
2. Visitor sees current builder signals and source receipts.
3. Visitor enters name and email to unlock the install command.
4. Visitor installs the skill and asks their agent for on-demand or scheduled
   delivery.
5. The lead is stored in the shared `radar_leads` table with
   `product = "george-builder-radar"` and `source = "website-install-gate"`.

## Lead Magnet

Primary lead magnet:

- installable Builder Radar skill
- latest public feed
- archive search
- delivery setup through the user's agent

The lead magnet promise:

> Stop doomscrolling AI-agent launches. Let your agent deliver the builder
> signals and receipts worth acting on.

## Paid Value Hypotheses

The first paid offer should be downstream of the same pain, not a random
newsletter upgrade.

Candidate paid offers:

1. **Operator Radar Pack**
   - curated weekly feed
   - private source list
   - prompt templates
   - proof-object checklist
   - best for indie builders and technical creators

2. **Team Builder Radar Setup**
   - install and configure radar delivery for a team
   - route sources into Slack/Discord/email
   - add private source watchlists
   - best for startups and AI-tool teams

3. **Proof-Object Sprint**
   - one week to turn a team's internal workflow into a public demo, launch
     note, or credibility artifact
   - best for companies with real product work but weak proof packaging

## Near-Term Site Implication

The homepage should prioritize:

- current public signals
- source receipts
- skill install as the primary CTA
- contribution/request intake

Email collection exists to unlock the skill and keep a qualified lead list. It
should not imply that generic email delivery is the main product until an
actual email digest workflow exists.
